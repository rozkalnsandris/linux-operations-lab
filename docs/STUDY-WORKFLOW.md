# Study Workflow

## Daily loop

1. **Recall** — answer from memory before opening notes.
2. **Learn** — use official documentation for the new concept.
3. **Do** — perform a hands-on lab.
4. **Incident/Ticket** — investigate a small broken scenario.
5. **English evidence** — write a concise technical update.
6. **Prove** — commit a useful artifact when the work is worth showing.

## Troubleshooting discipline

Do not begin with random fixes. Use:

1. Clarify symptom and impact.
2. Collect evidence.
3. Narrow the failure domain.
4. Form one hypothesis.
5. Test it.
6. Fix only the confirmed cause, or escalate with evidence.
7. Verify the technical and user-visible result.
8. Document what happened.

## Weekly Saturday challenge

Saturday is primarily a blind operations challenge, not another theory day. The root cause should not be revealed before diagnosis. The resulting evidence can become an incident record, runbook improvement or postmortem.

## GitHub rule

Not every note deserves a commit. Prefer artifacts that demonstrate judgment, troubleshooting, reproducibility or clear communication.
